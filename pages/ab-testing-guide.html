CH.1 A/B测试完整流程

1.1 假设提出：从数据异动到可验证假设

A/B测试不是"随便试两个方案看哪个好"，而是用数据验证一个预先设定的因果假设。好的假设 = 业务洞察 + 可操作变量 + 可量化预期。

差的假设："试试新的召回文案"
好的假设："将召回Push标题从'欢迎回来'改为包含具体玩法更新的版本，预计点击率从18%提升至21%，因为5.28报告显示超长期流失用户对'玩法更新'的记忆保留最强"

从5.28报告发现到可测试假设

发现数据支撑可测试假设
曝光不足是核心瓶颈短期仅35.7%被触达，64-84%完全未触达覆盖率35.7%→50%，回流率1.94%→2.5%
触达后回流率提升1.7-2.0x触达用户回流率远高于未触达用户触达本身有效，问题在覆盖面

假设的规范性检验

一个好假设必须同时满足三个条件：

  1. 可证伪：存在实验结果能推翻假设。覆盖率提至50%但回流率不变 → 推翻。
  2. 可操作：有明确的干预手段。"手Q召回Push从日均1次增至2次"。
  3. 可量化：有明确的预期效果。"回流率从1.94%提升至2.5%"。

"在提出假设阶段，我会用5.28报告的数据来锚定基线。比如短期流失用户的曝光覆盖率只有35.7%，触达后回流率提升1.7-2.0x，这意味着'曝光不足'是比'触达效率'更核心的瓶颈。所以我优先测试的假设不是'如何优化触达内容'，而是'如何提升曝光覆盖率'。"

1.3 样本量计算

n = (Zα/2 + Zβ)2 × [p1(1-p1) + p2(1-p2)] / (p1 - p2)2

其中 Zα/2=1.96（α=0.05双尾），Zβ=0.84（β=0.2，80%功效）

实战计算：短期流失用户曝光覆盖率提升

  • 基线回流率 p1 = 1.94%（2026-04整体）
  • 预期回流率 p2 = 2.5%（覆盖率35.7%→50%，触达后1.7-2.0x提升）
  • α = 0.05, β = 0.2
Python
import math
from scipy import stats

def sample_size_proportion(p1, p2, alpha=0.05, beta=0.2):
    z_alpha = stats.norm.ppf(1 - alpha/2)  # 1.96
    z_beta = stats.norm.ppf(1 - beta)       # 0.84
    numerator = (z_alpha + z_beta)**2 * (p1*(1-p1) + p2*(1-p2))
    denominator = (p1 - p2)**2
    return math.ceil(numerator / denominator)

CH.2 实验执行中的常见问题

2.1 新奇效应（Novelty Effect）

新功能/新内容上线初期，用户因"新鲜感"产生的临时行为提升，不代表长期效果。

时期腾讯视频短期回流率说明
1月/3月重点投入期25-30%高投入=高覆盖=高回流
4月淡季15.21%投入减少，回流率下降

5.28报告提到"活动和活动中心回流人数排前二（18.7万/15.6万）"，但活动类"触达广但留存浅"。新召回活动首周回流率暴增可能是新奇效应——7日后留存不住。

应对策略

策略做法适用场景
延长观察期至少2周，用后7天数据决策所有召回类实验
衰减分析画日回流率曲线新活动/新素材上线
Cohort分析按入组日分组对比长期运行实验
排除首日数据不用Day1数据Push类即时触达

"5.28报告中腾讯视频渠道重点投入期回流率25-30%、淡季15%，这说明投入带来的提升有衰减成分。所以我设计A/B测试时不会只看首周数据，而是要求实验运行至少14天，用后7天的稳态数据做决策，同时画出日回流率趋势线检测衰减。"

2.2 溢出效应（Spillover Effect）

实验组的干预效果"溢出"到对照组，导致两组差异被低估。

5.28报告揭示了社交维度溢出风险：中期流失用户"回流后更多时间在社交系统"；超长期回流用户7日日均时长58.6小时；42.9%超长期用户仍在其他腾讯游戏活跃。

"5.28报告发现中期流失用户回流后更多时间在社交系统，这意味着社交召回实验极易产生溢出。如果按个人分流，实验组用户邀请好友回归，好友可能在对照组，导致两组差异被稀释。所以我会按社交圈cluster分流，确保一个好友圈内的用户要么全在实验组，要么全在对照组。"

2.3 样本比例失调（SRM）

Sample Ratio Mismatch——实验组和对照组的实际样本比例与预期不一致。这是最容易被忽视但后果最严重的问题。

严重程度表现处理
轻微 p>0.05随机波动正常分析
中等 0.01<p<0.05可能有分流bug排查后决定是否继续
严重 p<0.01确定有分流问题立即暂停实验，修复后重跑

"5.28报告显示手Q贡献60-67%回流UV，如果分流逻辑对手Q用户有偏向，就会导致SRM。我的做法是：每日卡方检验检查实验组/对照组比例，如果p<0.01立即暂停。这不是小题大做——SRM意味着分流有系统性偏差，任何结论都不可信。"

2.4 辛普森悖论

分组看实验有效，汇总后反而无效（或反之）。5.28报告的数据结构天然容易产生此悖论——4层流失分层的规模差异极大：

2.5 选择偏差与幸存者偏差

5.28报告关键发现：回流用户付费率 61.3% vs 流失用户 16.3%，差距45个百分点。

不能说"付费导致回流"——更可能是深度参与的用户既付费又留存，付费和回流都是深度的结果，不是因果关系。类似地，"回流用户历史活跃天数是流失用户5-8倍"是相关性，不意味着"增加活跃天数就能提升回流率"。A/B测试的价值在于用随机分组消除选择偏差，验证因果关系。

CH.3 结果分析方法

3.1 显著性检验

数据类型检验方法炫舞案例
比例类双样本Z检验回流率、点击率、曝光率
连续型双样本t检验回流后7日日均时长
计数类泊松检验/Mann-Whitney U活跃天数、付费次数
分层比例Cochran-Mantel-Haenszel按流失分层汇总
 
Python
# 双样本比例Z检验
from scipy import stats
import numpy as np

def two_proportion_z_test(s_a, n_a, s_b, n_b, alt='greater'):
    p_a, p_b = s_a/n_a, s_b/n_b
    p_pool = (s_a + s_b) / (n_a + n_b)
    se = np.sqrt(p_pool * (1-p_pool) * (1/n_a + 1/n_b))
    z = (p_b - p_a) / se
    p_value = 1 - stats.norm.cdf(z) if alt == 'greater' else 2*(1-stats.norm.cdf(abs(z)))
    return {'z': z, 'p_value': p_value, 'significant': p_value < 0.05,
            'control': p_a, 'experiment': p_b, 'lift_pp': (p_b-p_a)*100}

# 5.28数据：对照组16350人回流317人(1.94%) vs 实验组16350人回流409人(2.50%)
result = two_proportion_z_test(317, 16350, 409, 16350)
# Z ≈ 2.53, P ≈ 0.006 → 统计显著 ✅

P值的正确解读

说法正确？
"P值=0.03意味着有3%的概率实验无效"❌
"如果实验真的无效，观察到当前效果的概率只有3%"✅
"P<0.05就一定能上线"❌ 还要看效果量和业务意义
"P>0.05说明实验没效果"❌ 可能是样本量不够

3.2 效果量估计

统计显著性 ≠ 业务意义。P值只告诉"差异是否真实存在"，效果量告诉"差异有多大"。

效果量类型计算方式炫舞案例
绝对提升p实验 - p对照+0.56pp
相对提升Δp / p对照+28.9%
增量回流人数Δp × 流失池规模0.56% × 32.7万 ≈ 1,831人/月
增量收入增量人数 × ARPU1,831 × ARPU估算

"5.28报告告诉我短期流失池32.7万人，即使回流率只提升0.56pp，每月也能多召回1,831人。Cohen's h只是'小效果量'，但对业务每月近2000人增量回流是有价值的。所以我会同时报告统计效果量和业务效果量，让决策者看到完整画面。"

3.3 置信区间解读

CI情况解读决策

CI跨0但上界>业务阈值可能有效但不确定延长实验

CH.4 面试实战：STAR法则案例模板

4.1 主案例：短期流失用户触达覆盖率提升实验

S — Situation 背景

我在腾讯IEG负责炫舞手游数据分析。5.28专项报告发现曝光不足是回流率低迷的核心瓶颈：

  • 2026年4月，流失池规模达551万人，整体回流率仅1.94%，相比2024年7月的4.86%持续下降
  • 曝光率从37.86%下降至20.57%，持续萎缩
  • 64-84%的流失用户完全未被触达
  • 触达后回流率能提升1.7-2.0倍，说明触达本身有效，问题出在覆盖面不足
  • 短期流失用户曝光覆盖率仅35.7%，远未饱和

渠道效率矩阵：手Q贡献60-67%回流UV但覆盖深度不足，心悦效率3.1-4.3x但量级太小。最优运营区间在曝光率28-35%、曝光转化率6-8%。

T — Task 任务

设计A/B测试，验证提升短期流失用户的触达覆盖率能否有效提升回流率。核心问题：覆盖率35.7%→50%，回流率能提升多少？增加触达是否边际衰减？不同渠道增量效率如何？

A — Action 行动

① 指标设计：OEC=回流率 / 辅助=曝光率、点击率、曝光转化率 / 护栏=7日留存率（5.28基线：短期37.7h）、ARPU、非召回渠道回流率

② 样本量：基线1.94%，MDE=+0.5pp，每组7,600人。短期池32.7万，5天入组，14天出结论。

③ 分流：user_id hash简单随机（Push实验无溢出风险）+ 分层验证R级/渠道均衡 + 日频SRM卡方检验

④ 实验设计：对照组=标准Push（日均1次，覆盖率35.7%）| 实验组=增加频次+扩展覆盖（日均2次，目标50%）

⑤ 监控：SRM自动暂停（p<0.01）、护栏降5%预警、核心指标连续3天逆向预警。用后7天稳态数据决策（避免新奇效应）。

R — Result 结果与反思

覆盖率35.7%→50%，推算回流率1.94%→2.5%（+0.56pp，+28.9%），每月增量回流约1,831人。护栏指标无异常。

反思与迭代：

  • 边际衰减：心悦UV小但效率高，扩量后可能效率下降 → cohort分析看曝光频次曲线
  • 分层异质性：每1万次曝光短期906回流、超长期453（效率差2倍）→ 必须按流失分层细分
  • 相关性≠因果性：付费率61.3%vs16.3%≠付费导致回流 → A/B随机分组验证因果

4.3 "实验不显著"怎么讲

  1. 排查统计功效：事后功效<80% → 样本量不够。短期池32.7万不存在此问题，但心悦渠道（UV小）可能。
  2. 细分分析：整体不显著但某些层可能显著。4层效率差2倍，超长期64%权重可能稀释短期效果。
  3. 检查护栏指标：即使核心不显著，确认无负面影响 → 实验至少安全。
  4. 分析原因并迭代：干预力度不够？方向错误？时机问题（4月淡季）？
  5. 文档化：不显著的实验同样有价值——"这条路走不通"节省了全面上线资源。

4.4 高频追问 Q&A

Q1: 你怎么确定MDE？

跟业务方对齐："回流率提升多少你们才会改变运营策略？"运营说0.5pp就值得加大投放 → 0.5pp作为MDE反算样本量。如果算出样本量在可用池内无法达成，回去讨论是否降低MDE或延长周期。

Q2: SRM怎么处理？

实验上线第一天就跑SRM检测。5.28显示手Q贡献60-67%回流UV，分流逻辑对手Q偏向就会导致SRM。每日卡方检验，p<0.01立即暂停。排查分流代码、渠道分配、数据延迟，修复后从零重跑。

Q3: 如何区分相关性与因果性？

5.28报告例子：回流用户付费率61.3% vs 流失16.3%，差45pp。不能说"付费导致回流"——深度参与的用户既付费又留存，两者都是深度的结果。A/B随机分组消除了选择偏差，如果实验组回流率确实显著高于对照组，才能建立因果关系。

Q4: 多变量实验怎么处理？

5.28有4分层×4渠道×6R级=96分组，样本量不够。做法：①主实验只测1个变量 ②析因设计测2变量时确保2×2=4组样本量充足 ③分层作为协变量纳入分析 ④必须多变量用正交设计减少组合数。

Q5: A/A测试了解吗？

两组都不做干预，验证分流系统本身没有偏差。正式A/B前先跑3-5天A/A，确认：①两组回流率差异<0.1pp ②SRM通过 ③各维度均衡。A/A都通不过，说明分流逻辑有bug，必须先修好。

Q6: 怎么向上汇报A/B测试结果？

三层汇报：①一句话结论——"回流率1.94%→2.5%，月增1,800人，建议上线" ②关键数据——P值、CI、护栏状态 ③细分洞察——分层效果差异、渠道效率对比。绝不只丢一个P值。5.28教会我一件事：不同分层效率差2倍，只看汇总会错过关键决策信息。

class ABTestAnalyzer:
    """A/B测试完整分析工具"""
    def __init__(self, ctrl_s, ctrl_n, exp_s, exp_n, alpha=0.05):
        self.ctrl_s, self.ctrl_n = ctrl_s, ctrl_n
        self.exp_s, self.exp_n = exp_s, exp_n
        self.ctrl_rate = ctrl_s / ctrl_n
        self.exp_rate = exp_s / exp_n
        self.alpha = alpha

    def z_test(self, alt='greater'):
        from scipy import stats
        import numpy as np
        p_pool = (self.ctrl_s + self.exp_s) / (self.ctrl_n + self.exp_n)
        se = np.sqrt(p_pool*(1-p_pool)*(1/self.ctrl_n + 1/self.exp_n))
        z = (self.exp_rate - self.ctrl_rate) / se
        p = 1-stats.norm.cdf(z) if alt=='greater' else 2*(1-stats.norm.cdf(abs(z)))
        return {'z':z, 'p_value':p, 'significant':p
